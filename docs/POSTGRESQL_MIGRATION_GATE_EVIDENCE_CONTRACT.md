# PostgreSQL Migration Gate — Evidence Contract

Status: **OPEN / NOT LOCKED**

This contract defines the minimum evidence required before the PostgreSQL migration gate may be marked passed. A green unit test or a successful local run alone is insufficient.

## Identity and provenance

Every evidence bundle MUST identify:
- repository and branch;
- full 40-character commit SHA under test;
- workflow run ID and attempt number;
- PostgreSQL server version and database identity (no credentials);
- UTC start/end timestamps for the workflow, each competing process, and each migration attempt;
- runner/host identity and test command.

The commit SHA in the manifest MUST equal the checked-out SHA recorded by the workflow, the commit tested by the concurrency workflow, and the commit named by every report.

## Required evidence

1. **Concurrency workflow:** completed successfully on the exact commit SHA. The workflow must launch two independent processes against the same PostgreSQL database and migration target.
2. **Two-process trace:** each process records PID, PostgreSQL backend/session PID, start/end UTC timestamps, exit status, lock acquisition/wait/release events, and migration result. Logs must establish actual overlap, not merely sequential execution.
3. **JUnit report:** machine-readable test report retained as a workflow artifact and associated with the exact run/attempt.
4. **Migration file hashes:** SHA-256 for each ordered migration file, plus a deterministic database-schema checksum after migration. The checksum algorithm and included schema objects must be documented; compare expected and observed values.
5. **Schema version integrity:** record total row count, unique version count, all applied version identifiers, each `applied_at` timestamp, and verify there are no duplicate version identifiers or missing required versions.
6. **Failure/retry proof:** deliberately fail a migration after lock acquisition; capture the failure and rollback result; prove the lock is released; retry the same migration and show success. A timeout alone is not proof of lock release.
7. **Evidence manifest + CI artifact:** publish all logs, reports, checksums, and metadata as one downloadable artifact. The manifest contains SHA-256 for every included file and the exact commit SHA.

## Required assertions

- Exactly one authoritative successful application per migration version.
- Concurrent runner cannot apply the same version twice or leave partial schema changes.
- Failure does not leave the migration lock held or a false successful version record.
- Retry succeeds without duplicate schema objects or version records.
- Schema checksum and migration-file hash list match the recorded expected values.
- All assertions are evaluated against PostgreSQL, not SQLite or mocks.

## Suggested artifact layout

```text
migration-gate-evidence/
  manifest.json
  workflow-metadata.json
  process-a.jsonl
  process-b.jsonl
  postgres-server.json
  migration-files.sha256
  schema-checksum.json
  schema-version-report.json
  junit.xml
  failure-and-retry.jsonl
  test-summary.txt
```

## Manifest minimum fields

```json
{
  "repository": "butnee-sys/gerchain",
  "commit_sha": "<full 40-character SHA>",
  "workflow_run_id": "<GitHub Actions run ID>",
  "run_attempt": 1,
  "postgres_version": "<server version>",
  "started_at_utc": "<RFC3339 UTC>",
  "completed_at_utc": "<RFC3339 UTC>",
  "result": "PASS|FAIL",
  "files": [
    {"path": "junit.xml", "sha256": "<sha256>"}
  ]
}
```

Placeholder values are not evidence. A PASS result is valid only when generated by the workflow from collected execution data. Do not manually set PASS.

## Gate decision

Mark **PASS** only if every required evidence item exists, all hashes verify, all assertions pass, and all artifacts point to the same commit SHA and workflow run. Otherwise report **OPEN / NOT LOCKED** with the missing evidence listed explicitly.
