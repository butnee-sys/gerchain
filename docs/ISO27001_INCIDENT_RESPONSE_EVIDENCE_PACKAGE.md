# NEF–G-3–GerChain — Incident Response Evidence Package

**Status:** Evidence template — organizational completion required
**Branch:** `docs/iso27001-alignment`

## 1. Objective

Demonstrate that information-security incidents are identified, recorded, assessed, contained, recovered, communicated where required and used for corrective improvement.

## 2. Required evidence

### Incident procedure
- approved procedure owner;
- severity/classification criteria;
- escalation path;
- roles and responsibilities;
- communication/notification criteria;
- evidence preservation requirements.

### Incident register
- incident identifier;
- detection date/time;
- affected asset/service;
- classification;
- assigned owner;
- actions taken;
- recovery/verification;
- notification decision;
- closure date;
- lessons learned.

### Exercise / test
- exercise date;
- scenario;
- participants;
- expected response;
- observed response;
- gaps;
- corrective actions;
- effectiveness verification.

## 3. Technical boundary

CORE logging, Witness Chain, auditability and reconciliation provide supporting evidence for detection, traceability and investigation. They do not replace the organization's approved incident-response procedure or operational incident records.

## 4. Evidence protection

Incident evidence may contain sensitive operational, personal, legal or security information. Store it only in an approved controlled location and never place secrets or unnecessary personal data in this repository.

## 5. Acceptance test

Move from **MISSING** to **AVAILABLE** only when the procedure is approved and an operational incident record or exercise demonstrates the process has been executed and reviewed.
