# EA-35.13 — PostgreSQL Production Re-performance Protocol

Status: IN PROGRESS / NOT LOCKED

## Purpose

This protocol defines the evidence required before EA-35 can be declared production-ready.

## Required runtime

- PostgreSQL 16
- `ProductionRuntimeFactory`
- Canonical Ledger authority
- Canonical Escrow aggregate
- transaction-aware Ledger boundary
- Witness
- transactional Outbox
- durable Idempotency

## Required evidence

1. Factory construction establishes `is_canonical_ledger_authoritative == True`.
2. Canonical tables exist in PostgreSQL.
3. Production entrypoint boots against PostgreSQL and exits only on controlled termination.
4. FUND creates exactly one value movement.
5. LOCK creates state/evidence only and no value movement.
6. RELEASE moves value exactly once.
7. REFUND uses the authoritative refund destination.
8. CANCEL CREATED is state-only.
9. CANCEL FUNDED reverses value to the authoritative sender.
10. SETTLEMENT uses the Canonical Ledger and no secondary balance authority.
11. Replay is idempotent.
12. Conflicting replay is rejected.
13. Deep value-truth reconciliation returns matched.
14. Rollback leaves no partial value/evidence state.
15. The exact tested commit SHA is recorded by CI.

## Lock rule

No GREEN or production lock may be declared from source inspection alone. A fresh PostgreSQL execution at the exact candidate SHA is mandatory.
