# NEF–G-3–GerChain — Corrective Action Requirements

**Status:** Governance framework — active closure evidence pending

## 1. Objective

Ensure identified nonconformities, incidents and control weaknesses are corrected using a traceable and risk-based process.

## 2. Lifecycle

`Identify → Contain where necessary → Determine cause → Define correction → Assign owner → Set deadline → Implement → Verify effectiveness → Close → Record lessons`

## 3. Required record

Each corrective action should contain:

- source/finding;
- affected requirement/control;
- risk and impact;
- immediate correction;
- root-cause analysis where appropriate;
- action owner;
- target date;
- implementation evidence;
- effectiveness test;
- closure decision.

## 4. Escalation

Major or systemic issues affecting confidentiality, integrity, availability, legal compliance, privileged access, cryptographic protection or core transaction integrity shall be escalated according to organizational governance.

## 5. CORE boundary

A technical defect fixed in GerChain is evidence of technical correction. It does not automatically prove that the corresponding organizational corrective-action process is implemented.

## 6. Gate

**Corrective-action governance: PARTIAL — framework defined; operational records and effectiveness verification required.**
