# NEF–G-3–GerChain — Information Security Incident Response Requirements

**Status:** Controlled requirements — evidence pending

## 1. Incident lifecycle

`Detect → Record → Triage → Contain → Eradicate → Recover → Verify → Notify → Learn → Correct`

## 2. Required procedure

The organization shall define:

- what constitutes an information-security incident;
- reporting channels;
- severity/priority criteria;
- responsible roles;
- escalation path;
- evidence preservation;
- containment and recovery authority;
- legal/regulatory notification assessment;
- communications authority;
- post-incident review;
- corrective-action tracking.

## 3. Required records

- incident register;
- incident ID;
- date/time;
- affected asset/service;
- classification/severity;
- actions taken;
- evidence references;
- decision/approval records;
- recovery result;
- lessons learned;
- corrective actions and closure.

## 4. Exercise requirement

At least one controlled incident-response exercise should be performed before independent assessment readiness, with findings and corrective actions retained as objective evidence.

## 5. Technical boundary

Application logs, Witness Chain evidence, reconciliation records and recovery tests are technical evidence sources. They do not replace the organization's incident-management process.

## 6. Gate

**Incident response: MISSING — approved procedure and exercise evidence required.**
