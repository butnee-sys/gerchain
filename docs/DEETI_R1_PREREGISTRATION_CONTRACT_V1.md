# DEETI R1 Pre-registration Contract v1

**Status:** PROVISIONAL — PRE-REGISTRATION DRAFT
**Research state:** R0

## 1. Purpose

This document freezes the analytical rules that can be frozen before confirmatory outcome data are inspected. It is designed to prevent outcome-dependent specification changes.

## 2. Primary causal question

For the same underlying digital economic transaction, does assignment to a transaction process implementing the Escrow Trinity capability improve transaction reliability compared with an otherwise equivalent control process?

## 3. Primary endpoint

`O1 = completed initiated transactions`.

\[
O1_i = 1 \quad\text{if and only if transaction } i \text{ satisfies the frozen completion rule.}
\]

The primary estimand for a randomized design is:

\[
ATE = E[O1(ET)] - E[O1(Control)]
\]

The primary estimand is an absolute probability difference, not a relative percentage improvement.

## 4. Treatment assignment

### Control

The baseline legitimate transaction process without the additional bundled Escrow Trinity capability.

### ET treatment

The same underlying transaction process plus the pre-specified bundle:

1. Trust capability;
2. Transparency capability;
3. Verified Fulfilment capability.

The economic object/service, eligibility, value range, observation window, and terminal-state definitions must remain common across arms.

## 5. Randomization rule

Preferred design: individual transaction-level randomization.

If interference, operational constraints, or repeated-participant effects make individual randomization invalid, the protocol must explicitly declare a cluster or participant-level assignment rule before confirmatory outcome inspection.

Assignment must be generated by a reproducible procedure and recorded before transaction lifecycle execution.

## 6. Blinding and independent outcome coding

Where technically feasible, the person coding O1 must not know treatment assignment.

At minimum:

`TreatmentAssignment → TransactionLifecycle → IndependentO1Coding`

O1 coding must not be changed because of treatment status.

## 7. ETI measurement

ETI is secondary to the primary treatment-vs-control comparison:

\[
ETI = \frac{T + Tr + Tf}{3}
\]

where:

- `T` = Trust component;
- `Tr` = Transparency component;
- `Tf` = Verified Fulfilment component.

ETI components must be recorded from evidence generated before the terminal O1 outcome whenever the construct requires temporal ordering.

## 8. Practical-effect threshold

A minimum practically meaningful absolute improvement `δ` is required before confirmatory testing.

**δ is NOT YET FROZEN.**

It must be justified independently from:

- baseline transaction reliability;
- operational consequences of failure;
- economic/time consequences;
- feasible intervention effect;
- measurement precision;
- stakeholder decision threshold.

Existing literature may inform the plausibility range but cannot determine δ solely from a different population or outcome. For example, prior escrow experiments report significant settlement effects under specific asymmetric-information bargaining conditions, but those findings are not directly transferable as the DEETI effect threshold. citeturn1search1turn1search6

## 9. Alpha and power

Default planning values may be proposed, but they are not frozen until the experimental domain and practical δ are frozen.

Candidate defaults:

- two-sided α = 0.05;
- power = 0.80 or higher;
- equal allocation unless operational constraints require otherwise.

Final sample size must be calculated only after δ, baseline rate, allocation, clustering/repeated-measures structure, and expected missingness are frozen.

## 10. Exclusions

Exclusions must be defined before outcome inspection and cannot depend on whether O1 is successful.

Permitted categories include:

- invalid initiation;
- duplicate observation identifier;
- technical failure preventing transaction initiation;
- protocol violation defined independently of outcome;
- missing mandatory pre-treatment eligibility information.

Post-treatment exclusions are not permitted unless the rule was pre-specified and applies independently of observed O1.

## 11. Missing data

Missingness must be classified as:

- missing completely before lifecycle start;
- missing treatment/exposure evidence;
- missing outcome evidence;
- administrative censoring;
- technical data loss.

The primary analysis must not silently convert missing O1 into success.

## 12. Primary statistical model

For individual randomized transactions, the primary comparison is the difference in O1 proportions between treatment and control, with a confidence interval and two-sided hypothesis test.

A regression-adjusted model may be used as a pre-specified precision analysis, but the unadjusted randomized comparison remains the primary estimand unless the final protocol explicitly changes this before outcome inspection.

## 13. Secondary analyses

Pre-specified secondary outcomes:

- O2 transaction friction;
- O3 failure/dispute rate;
- O4 evidence integrity;
- O5 conditional settlement performance;
- ETI component effects;
- ETI dose-response where meaningful variation exists;
- component ablation or factorial analysis if the design permits.

These cannot replace O1 as the primary endpoint after seeing results.

## 14. Falsification rules

The foundational capability claim is not supported if any of the following is observed:

1. treatment has no practically meaningful effect on O1;
2. the effect is statistically incompatible with the pre-specified direction;
3. the effect disappears under pre-specified robustness checks;
4. the effect is explained by baseline imbalance or an alternative mechanism;
5. removing an ET component does not materially affect the claimed mechanism when component necessity is being tested;
6. the effect is dependent on post-outcome measurement leakage;
7. independent reproduction fails.

A statistically significant result with negligible practical effect is not sufficient for the foundational claim.

## 15. Evidence integrity

Every confirmatory observation must have traceable provenance sufficient for an independent researcher to reconstruct:

`assignment → ET evidence → initiation → lifecycle → completion → O1`

The dataset, coding protocol, transformation code, analysis code, and exclusion log must be versioned.

## 17. Scientific boundary

This protocol does not assert that Escrow Trinity is already a proven foundational capability of Digital Economy. It defines a falsifiable experiment capable of producing evidence for, against, or insufficient to support that claim.
